## Delivered packet

- Scoped residual officer review uses the protected Phase 3F2 task and recomputes its immutable inputs before adoption. Current inherent/response/approved-plan provenance and completed treatment must still agree. Current scoring and control-effectiveness publications are rechecked under locks. Actual owners/assessors cannot adopt their own residual assessment (WF-05); combined-role Auditors stay read-only.
- Officer or downstream authority return requires justification and existing evidence. It records an immutable decision, cancels remaining open tasks for that residual round and opens an assigned Risk Owner reassessment prerequisite. Start consumes that prerequisite, pins current configuration and creates all eight fresh dimension tasks. No earlier scores, owner decisions, Ethics approvals or countersignatures authorize the new round. A missing/forged return prerequisite cannot open a replacement scored round.
- The immutable computed residual band selects authority. Low opens only the actual active Use-Case Owner task using airs.risk.accept.low. Medium opens the actual owner task, then one independent officer countersignature using airs.risk.accept.medium. The owner's Medium decision alone never accepts the risk or advances the case. The countersigner must differ from both the owner decision actor and the current Use-Case Owner if ownership changes; the actual Risk Owner cannot self-accept Medium+ even with extra roles (GEN-27).
- High opens a fresh independent Ethics task after officer adoption. Only its approval opens the Executive Team task using airs.risk.accept.high (L3). Ethics owners recuse (GEN-29); its approving actor cannot also perform the Executive acceptance. Returned High rounds require fresh Ethics approval. Existing inherent/AIUC Ethics decisions do not satisfy this residual gate.
- Critical opens only the Steering Committee task using case.approve.airs (L4), with outcomes restrict, stop or return. Plain accept/approve is rejected; no Critical acceptance permission exists. Restrict records SUSPENDED and stop records ARCHIVED against the actual AiUseCase, linked to the immutable Steering decision. A SQL guard prevents forged status writes, clearing a protected state or reopening an archived use case via a lower restriction outcome. No model/provider execution shutdown integration is claimed.
- Every decision requires written justification and 1–20 existing nondeleted DGOP evidence identifiers. Optional conditions are retained as up to twenty nonempty text entries in the append-only decision record. Conditions are recorded for future compliance/discharge work; no automatic condition execution is claimed.
- Low acceptance, completed Medium countersignature or High Executive acceptance advances AIRS to Decision Made and opens only one protected monitoring-preparation task. Critical restriction/stop does the same with riskAccepted=false. The case remains open; no cadence, recurring calendar instance, closure or notification delivery is fabricated.
- Calculation snapshots remain unchanged (their original adopted=false/riskAccepted=false are historical calculation facts). Current review/acceptance badges derive from the matching decision ledger, including returned/pending authority/accepted states. Current acceptance is not inferred from a stale parent assessment. AIRS capability reads now include existing band-acceptance grants, retaining deny-by-default live checks.
- Mutations use serializable transactions, optimistic risk versions, native task claims/completion, workflow events and required audit. Audit failure rolls back decisions, conditions, task routing, versions, case advancement and use-case status. Concurrent duplicate adoption/countersignature succeeds exactly once. Posted band/authority/actor/computed/accepted fields cannot grant authority.
