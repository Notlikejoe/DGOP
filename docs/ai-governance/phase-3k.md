# Phase 3K — Annual comprehensive organization-register review

Implemented locally together with 3L/3M, 2026-09-12. Each active native organization unit can register one annual AI risk-register calendar. Only an eligible Responsible AI Officer with the explicit cadence grant and complete register visibility may register or complete its Review task. Auditors have scoped read-only access; Risk Owner-only views cannot operate a comprehensive organization register. No new technology or dependency is introduced.

The protected calendar uses `ai_annual_review`, a 365-day interval and Saudi end-of-day deadlines. Each dated occurrence has a native Review task in a dedicated AIRS register-review case, without attaching the register to an arbitrary asset. It preserves an immutable source snapshot of non-sample, registered, currently visible AI risks and assessment history. The source snapshot is captured when a cycle opens. It does not automatically substitute for the officer's analysis of trends, control effectiveness or non-conformities.

Completion requires three written findings and 1–20 existing DGOP evidence IDs, records immutable officer/IP/server-date provenance, completes the original task/occurrence and atomically opens the next cycle in the same case/calendar. Next anchor equals the evidence-backed completion timestamp; no posted due date, officer identity or snapshot is accepted. Failed required audit, stale/duplicate completion and concurrent registration roll back safely. Generic calendar creation/updates cannot create or modify AI-owned review calendars; the generic generator excludes them. Annual native tasks continue to use the existing native SLA mechanism; the specialized 50/80/95/100 periodic-review signal engine is unchanged.

Full organization/domain/classification coverage is required for comprehensive reads and writes. Historical membership is checked against current scope and active records; if any source member becomes inaccessible, the snapshot fails closed. Annual officer identity is pinned; safe officer handover is future work rather than generic task reassignment. Review history, native dates/assignment/case linkage and completion-to-next scheduling have SQL immutability and deferred native guards.

The bilingual AI review operations screen reuses the DGOP page/hero, theme tokens, cards, forms, status chips and installed PrimeNG table. It displays annual cycle dates, pinned scores/history and immutable findings, with register selection and officer-only actions. Server capability flags control actions. No browser visual acceptance is claimed.

New coverage includes complete-register scope, Auditor/Risk Owner denial, source-member visibility changes, immutable findings/native history, invalid evidence, required-audit rollback, concurrent exactly-once registration/completion, server Saudi dates and retained-calendar next cycle. No active-app synchronization, live database, production source publication/import, workbook change, external message, push or deployment.
