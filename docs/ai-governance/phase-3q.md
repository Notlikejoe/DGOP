# Phase 3Q — Immutable closed-month review report archive

Implemented locally, 2026-09-13, with 3N/3O/3P. Eligible full-register Responsible AI Officers can explicitly capture one immutable periodic-review report per organization register and completed Saudi calendar month. Auditors and other authorized full-register readers can list and read captures. The existing bilingual review screen includes month selection, capture, a last-24-month archive and read-only measures.

The server derives month boundaries at UTC+03:00, rejects current/future or invalid months and supplies capture time. The database independently checks closed-month boundaries, eligible officer identity, capture-clock proximity and member provenance. Unique organization/month identity, serializable capture, append-only records and mandatory atomic audit prevent duplicate or partial capture. Clients cannot provide members, aggregate counts, actor or capture time.

Important measurement contract: a capture measures obligations whose pinned due dates fall within the chosen month, using the currently eligible organization register and completion state at capture time. It does not reconstruct historical month-end membership or backdate the report's as-of time. The UI states this explicitly. Numerator/denominator and no-due null state retain the live reporting formula. Immutable source member IDs/versions are stored internally; public payloads expose source count and measures, not member identities or creator/IP. Reading a capture fails closed if any stored member is outside current register visibility, including inactive assets. Subsequent eligibility restoration does not alter captured measures.

This is an explicit capture/archive packet, not an automatic monthly scheduler, external distribution, export or the full dashboard. Deployment migrations and business sign-off on scheduled historical reporting remain future gates.

Verification: real clean-install/baseline-upgrade PostgreSQL/Nest tests cover leap-year and December Saudi boundaries, current-month denial, Auditor write denial, injected computed-field denial, audit rollback, concurrent exactly-one capture, SQL immutability, member visibility changes and unchanged restored reads.
