## Operating contract

Open `/governance/ai-migration`, select an accepted preparation preview, then use its source-correction tabs. The officer builds a complete correction set; later versions should revise/copy the preceding set because captures always derive from the original immutable preview, not a mutable accumulated patch chain. DMO reviews the latest pending version independently. The officer captures the latest approved version after rechecking source, reference and directory pins and evidence. Returned versions cannot capture; superseded approved versions cannot create new captures, but already saved snapshots remain readable under current full live scope.

ISO source areas require an officer proposal and independent DMO publication before their version can be selected in a correction set. Revising/publishing a control version invalidates old control bindings for future captures; archived snapshots keep their original provenance. Publication records a source definition with suggestionsOnly=true, not controls implemented on a live risk. Source citations are retained workbook claims, not independent standards certification.

The whitelist excludes numeric scores, identifiers, sample flags, approval authority and unsupported fields. Corrected references remove only the corresponding label/version/missing-field issues. Corrected titles/directory/control bindings remove only their own preparation issues. Assessment provenance, computed differences, legacy approval authority, missing pilot data and other unresolved issues remain. Changing the original source or current reference/identity environment requires a fresh original preview and preparation review. API bodies cannot supply filesystem paths, raw reports or promotion/load flags.

Full live explicit AIRS read access, eligible governance identity and unrestricted organization/domain/classification scope are required for source content/history. Officer writes use refdata.propose.ai; DMO review/publication requires airs.library.import and refdata.publish. Auditor reads only; JWT role claims do not confer authority. Existing evidence must remain available for source/correction approvals and captures. Six new append-only correction/control tables use restrictive source FKs, unique request/round/review/publication/snapshot keys, evidence/shape checks, accepted-source membership and independent latest review/publication SQL guards.

## Verification and boundaries

API and Angular production builds, focused AI security contracts, and the isolated clean-install/baseline-upgrade PostgreSQL/Nest/HTTP harness cover version replay, unsupported/duplicate bindings, active directory and canonical reference selection, immutable raw data and ledgers, required-audit rollback, independent review, stale configuration/publications, ISO source/dimensions, duplicate source-area aliases, collision/dependent quarantine, snapshot digest round-trip, authorized Unicode exports and injected nested fields. Business risk/library/asset/case/action counts must remain unchanged. A case-sensitive assertion of the correctly rejected independent SQL publication was corrected during verification; no authority bypass was introduced.

No active-app synchronization, live migration, source workbook edits/imports, real source/policy publication, provider delivery, remote push or deployment. Browser appearance/load and production release certification are not claimed. Original documents/workbooks, About DGOP and shared native baselines remain preserved.
