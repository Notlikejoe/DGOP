## Operating contract

Use `/governance/ai-migration`, an accepted original preview and its current independently approved corrected snapshot. Select prepared library rows, enter reason/existing evidence, and create a source batch. DMO publishes each latest library proposal independently. Source candidates retain original identifiers; collisions never overwrite targets or reallocate source codes. The source batch and all native proposals/audits commit atomically. A later approved correction, source/reference/directory change or invalid evidence blocks new source proposals/publication until fresh preparation/correction review is completed.

Source imports create library proposal records only. Their archive compares reviewed source projections with actual immutable target versions; selectedLibraryZeroDiff is a genuine selected-library-proposal comparison, not a claim that all 66 rows, use cases, risk rounds, actions or the pilot migrated. Corrected snapshots keep loadedCount=0/targetCompared=false because they are immutable prior observations. Original raw cells/formulas/caches/exact numeric text/sample flags stay untouched. Overall migration zero-diff, complete source/pilot sign-off and production readiness remain pending.

Open a published library record to propose/review ISO control links. Links use current published version IDs and complete current R_IMPD dimension/competent-role/tie-order metadata. Explicit manual reviewed links are supported; automatic category-derived R_CATMAP mapping is not claimed. A new risk draft pins the latest approved link as suggestions. The assigned owner must select actual tags separately and complete the native causal intake. Draft selection cannot certify implemented controls, competent assessment, acceptance or publication. Registered risk tags remain immutable with the inherited submitted intake; continuing control changes require the existing governed procedure design rather than a bypass edit.

Treatment action selection uses the existing assigned owner, current adopted assessment, approved MITIGATE/TRANSFER strategy and preparation task. Pins are part of action planData, submitted action snapshot, independent approval and executor task/progress provenance. Existing immutable native submission/evidence/competence/RM-24/authority guards remain. Zero tags is an explicit valid selection; invalid arrays, duplicates, unknown/unpublished/superseded versions and stale dimension references fail closed.

Asset 360 reads require live eligible AIRS grants, native data_assets.view and current asset organization/domain/classification plus linked-use-case organization scope. Individual rows use own/org/all case visibility; the view explicitly describes the permitted population. Executive audience is aggregate only; Auditor reads only. All aggregate counts use complete permitted membership, and stale calculation provenance never contributes a residual score. Summary open-risk measures exclude closed/archived/rejected/cancelled cases. Register/history retain permitted registered history; mitigation uses only current approved native plans. Data Owners without AIRS grants gain no implicit AI disclosure. The existing asset schema, validators and registration facade are unchanged; reads do not create assets or write a risk summary into typeMetadataJson. The monolith uses current transactional reads rather than adding Kafka or an external read-model service.
